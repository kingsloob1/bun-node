# NestJS 11.1.27 → 12.1.3: platform-express, websockets, platform-ws, platform-socket.io, platform-fastify, microservices vs bun-nest

Scope: every commit from v11.1.27 to v12.1.3 that touches those six packages. That is 165 first-parent commits (`commits-pkgs.tsv`, release commits excluded), the 11 non-release commits of the 11.2.x branch (`commits-11.2-branch.tsv`), and the 59 sub-commits of the four branch merges that bundle work (09dba60ce = the v12.0.0 merge #16391, 0edc0ba3e, d047fbd31, 5530b9c46). **235 rows.**

Our code is cited from the worktree `bun-node-nest12-ae-1015` (branch docs/plan-nestjs-12, off develop 73bf4a00). Nest is cited by short hash or PR from `nest-src`. "First released in" is `git tag --contains <hash> --sort=v:refname | grep -E '^v1[12]' | head -1`. Tags v11.1.28–v11.2.1 sit on master before the 11.2.x branch point, so those commits are marked "(also 11.2.x)". Cherry-picks onto 11.2.x are named per row.

Method: for platform-express, websockets, platform-ws and platform-socket.io I read the diff of every commit, sub-commits included. For platform-fastify I read the commit message and touched paths, and the diff where it bears on the adapter contract. For microservices I used title plus touched paths, and checked that no row marked "transport internals" touches any package outside `packages/microservices` (script check: none does). PROBEs are small Bun scripts run on this host (Bun 1.4.4-canary.1); they live in `probes-platforms/` beside this file. No test suite was run. The "MEASURED" failures come from the parent's runs `test-bun-nest-nest12-run{1,2}.log` (Nest 12: 420 pass, 7 fail, deterministic).

### Top AFFECTS, ranked by impact

1. **`mapException` missing**: bad JSON and bad `%`-encoding are no longer turned into a Nest 400 by the core. Add `BunHttpAdapter.mapException` (SyntaxError/URIError → BadRequestException). 07603b53f #15075. MEASURED: 3 of the 7 Nest 12 failures.
2. **WS exceptions reach Bun clients in a new shape**: Nest 12 sends `{"event":"exception","data":…}` through `client.send` to any client with a numeric `readyState`, which bypasses our `installEmit` packet (BunWebSocketAdapter.ts:632-648). bc6b0880f/efe435191 #16366. MEASURED failure. Decide on the wire format and update docs and tests.
3. **Not-found handler ignores prefix and excluded routes**: setNotFoundHandler (BunHttpAdapter.ts:1302-1307) must scope to the prefix, add excluded exact paths, and skip other apps' prefixes. 33f37d627, e25575536, ab64da77f #17648, 529152191 #17923. MEASURED failure.
4. **A WS reply that cannot be serialised kills the process**: an unguarded `JSON.stringify` in the rxjs subscriber (BunWebSocketAdapter.ts:836-838 and :641, :1013, :856). An echo handler plus a deeply nested client payload exits Bun. 7e961f8b5 / 2618406e7 (also in 11.2.7). PROBE.
5. **Multipart field-name bounds**: no `fieldNestingDepth` / `fieldArrayIndexLimit`, and no LIMIT_FIELD_NESTING / LIMIT_FIELD_ARRAY_INDEX / INVALID_FIELD_NAME codes. `a[4294967294]` builds a 4294967295-length array. cf5204639 #18074, 8ff59f305 #17857, 4a4097836 #17421, multer 2.2→2.4 bumps. PROBE.
6. **handleDisconnect gets the client as its `reason`**: our bindClientDisconnect calls `callback(client, code, reason)` (:761), but Nest 12's callback is `(reason)`. ad5b731cd/722d27ad1 #16374.
7. **Peer ranges**: bun-nest peers `@nestjs/*` `^11.0.0` (package.json:95-97). Nest 12 platform packages require ^12. 3c25112b5.
8. **`return503OnClosing` + `beforeClose`**: neither exists (BunHttpAdapter.ts:1399-1418, 1576-1579). 319437ac3/26953bab7/decb89bf0 #16156, 4fa1e4e1f #18101.
9. **`$` exact-path middleware marker**: `forRoutes('*')` with a global prefix never runs on the bare prefix (createMiddlewareFactory :3361-3378). 82a77eb53 #17942. PROBE.
10. **MEDIA_TYPE versioning**: port `getMediaTypeVersion` (:3450-3495). 697ff89e0.
11. **StreamableFile source not destroyed** when the client left before the handler returned: fd held (reply :1214-1236). b64b3a054 #17973. PROBE.
12. **`reply()` drops a 0/NaN status** (:1210). e03cf5c86.
13. **QUERY method**: no `query()` verb and no QUERY case in getRequestMethodStr (:3264-3359). eac10cd2d #17162 (core agent overlaps).
14. **isRouteOrderSensitive**: should be false when BunRouter `routeSpecificity` is on. fcb3d7d3d #16954.
15. **ESM packaging**: rerun consumer-check against Nest 12. fa6d45da7.
16. **multer message wording** "Unexpected file field" (bun-common multipart/errors.ts:37). 28c5620ac #17769.
17. **`listen()` on a unix socket path** is refused (:984-989). b647b5762 #18053.
18. **Test-only** (behaviour is the core's; ours probably already fits): request-scoped gateways 5e3dc4d0a #16949 and follow-ups #17979 #17985 #17926 #18089. Gateway hook errors reach filters: b6295c799 #18048.

- **G1** No `setOnRequestHook` / `setOnResponseHook` (inherited no-ops). c9c251ca1, 8857ab6a7.
- **G2** `reply()` does not force application/json for an error body under a non-JSON Content-Type, and logs nothing. 1685a435b.
- **G3** No module-level upload options (MulterModule) and no function-valued `limits`. 31d8c93f4.

- **G5** A WS handler error sends an ERROR packet carrying `err.message` (BunWebSocketAdapter.ts:846-857). IoAdapter/WsAdapter log it and send nothing. 4247f6e5d.
- **G6** A StreamableFile stream error is only logged (`errorLogger`, BunHttpAdapter.ts:1232-1234). Express calls `body.errorHandler(err, response)`. Unchanged since 11.
