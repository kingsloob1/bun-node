## Per item

### 1. Built-in cookies (12.1, #17834 58e13ed7a)
- **Nest 12**: `cookies: { secret }` builds a `CookieSigner` shared with the adapter (`core/nest-application.js:440-450`, `setCookieSigner?.()`); `AbstractHttpAdapter.setCookie/clearCookie` serialise and call `this.appendHeader(res,'Set-Cookie',…)` (`core/adapters/http-adapter.js:261-292`); `@Cookies(name?)` / `@SignedCookies(name?)` (`common/decorators/http/route-params.decorator.js:360,389`) read `req.cookies` when it is an object, else parse `req.headers.cookie` once per request (`core/helpers/cookies/request-cookies.js:21-26`); signed cookies use Nest's signer on the raw header, else fall back to `req.signedCookies` minus `false`, else throw (`:47-71`).
- **express@12 (measured)**: setCookie/clearCookie/signed → `plain=v%201; Path=/; HttpOnly`, `signed=s%3Av2.<sig>; Path=/`, `gone=; Path=/; Max-Age=0; Expires=Thu, 01 Jan 1970…`; `@Cookies()` raw values (`j:{…}` string, `q` unquoted); `@SignedCookies()` with secret `{s:'v'}`, bad signature undefined; without a secret 500.
- **bun@12 (measured)**: Set-Cookie byte-identical; signed verification identical (Nest's signer reads our `req.headers.cookie`); signed fallback to our `req.signedCookies` (with `request.parseCookies.secret`) identical to express+cookie-parser. Differences: `j:` values arrive parsed (our default cookie parse = cookie-parser's JSON cookies; same as express **with** cookie-parser); quoted value keeps quotes (G18); no secret → 200 `{}` (our `signedCookies` is always an object — same as express with cookie-parser; doc only); `parseCookies:false` → `@Cookies()` `{}` (G17). No double-parse conflict otherwise: Nest parses the header itself only for signed cookies when it has a secret.
- **bun@11**: n/a (no decorator). **Verdict**: parity on writing; gaps G17, G18.

### 2. CSRF protection and security headers (12.1, #17836 555c2ce23; #17941 4bf2b404a)
- **Nest 12**: `enableCsrfProtection()` / `useSecurityHeaders()` must be called before init (`core/nest-application.js:268-286, 468-478`); one `HttpSecurityHook` registered via `httpAdapter.registerSecurityHook` at call time (`:485-492`), whose default implementation is `this.use((req,res,next)=>…next(error))` (`core/adapters/http-adapter.js` registerSecurityHook); the hook calls `response.setHeader/removeHeader` then the Go-style cross-origin check reading `request.headers[...]` (`core/security/http-security-hook.js:31-41`, `cross-origin-protection.js:201-218`). Contract: runs for every request before body parsing; rejection goes to the exception layer (`common/interfaces/http/http-server.interface.d.ts:520-539`).
- **express@12 (measured)**: GET 200 with 12 helmet headers; cross-site POST 403 `{"message":"Cross-origin request detected from Sec-Fetch-Site header","error":"Forbidden","statusCode":403}` **with** the headers; same-origin/`Sec-Fetch-Site: same-origin`/no browser headers 201; trusted origin 201; excluded route 201 and prefixed exclusion works; malformed JSON cross-site 403; unmatched cross-site POST 403; after init → throws.
- **bun@12 (measured, fetch and served)**: every decision identical (BunRequest `headers` is a lower-case record; BunResponse has `setHeader/removeHeader`; our `use()` runs for unmatched and unprefixed paths). Gaps: 403s carry none of the security headers (G5); malformed JSON cross-site → 400 (G6; `deferBody:true` measured to fix). Plus the warning G19. Unprefixed 404 differs from express only by the routing-agent's known not-found shape.
- **bun@11**: n/a. **Verdict**: works, gaps G5, G6, G19.

### 3. Exception mapping (07603b53f "HTTP adapter error mapping"), `errorCode` (abce26ecc, a9bf20b69), #17709 788e886ae
- **Nest 12**: the exception layer throws `httpAdapter.mapException(err)` (`core/router/routes-resolver.js:96`); default returns the error unchanged (`core/adapters/http-adapter.js:229`), the SyntaxError/URIError → 400 mapping moved from core (11: `routes-resolver.js mapExternalException`) into `ExpressAdapter.mapException` (`platform-express/adapters/express-adapter.js:442-452`). `isHttpError` narrowed to http-errors / FastifyError / plain objects (`core/exceptions/base-exception-filter.js:65-89`), so `Error` + `statusCode` alone is now 500.
- **express@12 (measured)**: invalid JSON 400 BadRequestException shape; over limit 413; bad encoding 415; `/p/%FF` 400; `errorCode` serialised; `Error{statusCode:418}` 500 (route and middleware); http-errors 422; plain object 409; SyntaxError/URIError via `next` 400.
- **bun@12 (measured)**: same except G1 (invalid JSON shape, `/p/%FF` 500, SyntaxError/URIError 500) and G20 (plain object 500). 413 message is bun-common's ("Request body exceeds… 1024 bytes (received 4008 bytes)") vs "request entity too large" — pre-existing text difference. `03b` shows the objects reaching the filter: our JSON error is a `SyntaxError` with `status/statusCode/expose`, our `%FF` error a `URIError{status:400}`.
- **bun@11**: all 400s correct (core mapping); 418s honoured (old isHttpError). **Verdict**: regression G1; G20 pre-existing; #17709 and errorCode parity.

### 4. SSE (11.2.x–12.1.3)
- **Nest 12**: `RouterResponseController.sse` (`core/router/router-response-controller.js:47-195`), `SseStream` (`core/router/sse-stream.js`): headers from `res.getHeaders()` and `res.statusCode` read at commit (#18011 d10b7c08f), `Expires: 0` (#17963 5e6054d29; 11 sent `Expire`), empty stream commits headers (#17986 f0806c5bf), early disconnect settles (#17987 52687474b), unserialisable data → `event: error` and end (#18025 f4b5ff48b), id on a copy (#18086 336a555bd), comments (#17327 41d9f37b3), `retry: 0` (#17360 2edb01d0f), `@SseSignal()` (#17469 b2e7fb5e7), plain-route Observable stopped on disconnect (#17826 6b282d3e1). Uses `req.socket` (`once('close')`, `destroyed`, `setKeepAlive/NoDelay/Timeout`) and `res.writeHead/write/flushHeaders/writableEnded`.
- **express@12 vs bun@12 (measured, served)**: **zero differences** across ticks, `@Header`+`@HttpCode(202)`, imperative 203 + header, empty, BigInt, frozen message twice, comment+retry 0, early disconnect during async setup (signal aborted, producer never subscribed), mid-stream disconnect (unsubscribed, signal aborted), plain Observable route (unsubscribed). Only with `--strict`: bun adds `Content-Length` when the whole stream completes before the first flush (cosmetic).
- **bun@11**: old behaviours (Expire header, empty stream no headers, BigInt stuck, frozen → 500, no comments, no signal, plain Observable not stopped). **Verdict**: parity.

### 5. StreamableFile
- **Nest 12**: express `reply()` sets type/disposition/length if absent, `stream.once('error', body.errorHandler(err,res))`, `finished(response, …stream.destroy())` (#17973) (`platform-express/adapters/express-adapter.js:97-113, 481-486`); `StreamableFile.handleError` → 400 + message (`common/file-stream/streamable-file.js:15-25`).
- **express@12 (measured)**: headers OK; mid-stream disconnect destroys source; disconnect before reply destroys source; early error 400 "source failed"; custom handler 503.
- **bun@12 (measured)**: headers parity; mid-stream disconnect destroys source (also on bun@11, where express 11 did not); disconnect before reply → **not** destroyed (G10); early error → ECONNRESET, handlers not called (G11). **Verdict**: gaps G10, G11.

### 6. Shutdown / listen
- **Nest 12**: `close()` → `shutdown()` deduped per cycle (#18021 d89c725ee, `core/nest-application-context.js:132-164`): `prepareClose` (= `httpAdapter.beforeClose?.()`, `core/nest-application.js:60-62`), destroy hooks, beforeShutdown, `dispose` (adapter close, `listening=false` #17951 c9ee47a1a, `:63-73`), shutdown hooks; express `beforeClose/close/initHttpServer(return503OnClosing, forceCloseConnections)` (`express-adapter.js:211-220, 286-308`); listen contract: callback `(err?)`, resolves only if `address()` is non-null, string port = pipe path (`common/interfaces/http/http-server.interface.d.ts:289-308, 548-577`). Lifecycle hooks by module distance (`nest-application-context.js:283-330`) are core-only: not applicable.
- **express@12 (measured)**: in-flight request drained (200); request during shutdown hooks 200 (default) / **503 `Connection: close`** (return503OnClosing); close with an open SSE: never (default), 302 ms (force); listening reset; concurrent close → hooks ×1, adapter close ×1; port 70000 rejects RangeError; busy port rejects; socket path listens, `getUrl()` `http+unix://…`, request served.
- **bun@12 (measured)**: in-flight reset (G9); 200 with return503OnClosing (G7); open SSE closes in ~300 ms either way; listening reset ✓, concurrent close ✓ (core); busy port rejects ✓; port 70000 and socket path hang + unhandled rejection (G8).
- **bun@11**: listening stayed true and `getUrl()` returned a stale URL after close; concurrent close ran hooks twice (core, fixed in 12). **Verdict**: core fixes reach us; gaps G7, G8, G9.

### 7. Body parsing and Standard Schema
- **Nest 12**: `rawBody` via `registerParserMiddleware(prefix, rawBody)`/`useBodyParser(type, rawBody, …)` (`core/nest-application.js:143-147, 255-264`); `@Body/@Query/@Param/@RawBody({schema})` (`common/decorators/http/route-params.decorator.js:183-315`, 09c81568f); `StandardSchemaValidationPipe` (`common/pipes/standard-schema-validation.pipe.js`), `StandardSchemaSerializerInterceptor` (`common/serializer/standard-schema-serializer.interceptor.js`).
- **express@12 vs bun@12 (measured, zod 4.6.1)**: parity on rawBody for json/text/urlencoded and no body, `@Body({schema})` coercion + 400 messages, `@Query({schema})`, `@Param('id',{schema})`, serializer stripping. Differences, all pre-existing and not Nest-12-specific: `application/octet-stream` without a raw parser is parsed on bun (Buffer body + rawBody), express leaves it undefined; a `Buffer` returned by a handler is sent as bytes on bun and JSON-serialised on express (`express-adapter.js reply`: `isObject → json`); nested query `filter[x]=1` → `{filter:{x}}` on bun (picoquery), dropped on express 5's `simple` parser. Nest itself: `@RawBody({schema})` is **not validated on either adapter** — RAW_BODY maps to `'custom'` (`core/pipes/params-token-factory.js:3-14`) and the pipe skips `custom` unless `validateCustomDecorators` (`standard-schema-validation.pipe.js toValidate`). **Verdict**: parity.

### 10. HTTP QUERY (d7772cd10; e2e 4edffd334, 10f8eb1e3)
